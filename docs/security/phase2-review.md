# Phase 2 security review

Date: 2026-11-09. Scope: `main` after the Phase 2 merges (LINE identity: ID-token verification, member sessions, member data rights, inbound webhooks, credential verification, invitations, security events, SDK). Reviewer: the read-only `security-reviewer` agent; every finding verified by reading the code path end to end. Nothing from the Phase 1 review regressed.

## Fixed before the checkpoint

| Severity | Finding                                                                                                                                                                                                                                             | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1       | Accepting an invitation for an address that already had an account took a password, so a self-registered tenant could invite any email and sign in as that account with a phished or reused password, bypassing TOTP and the per-email login limit. | Existing accounts never accept a password: the invitee must be signed in as that account (dashboard bearer) and the acceptance fails otherwise with `sign_in_required`. The attempt counter is keyed per invited email like sign-in. A signed-in stranger cannot claim a new-address invitation either. Covered by `TestInvitationForExistingAccountRequiresSignIn`, `TestInvitationCannotBypassTOTP`, `TestInvitationForNewAddress`. The dashboard sends people to sign in and then back to the link. |
| P3       | Member sessions stayed valid after an app was disabled.                                                                                                                                                                                             | `AuthenticateMember` loads the app and refuses non-active apps.                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| P3       | Member idempotency outcomes stored profiles in plaintext and survived erasure.                                                                                                                                                                      | The member service stores outcomes with the encrypted codec and erasure deletes the member's idempotency scope in the same transaction.                                                                                                                                                                                                                                                                                                                                                                |
| P3       | Erasure left IP and user agent on consent records.                                                                                                                                                                                                  | Migration 00005 grants `UPDATE (ip, user_agent)` on `member_consents`; erasure blanks both while keeping version and time as proof of consent.                                                                                                                                                                                                                                                                                                                                                         |
| P3       | The verify-endpoint fallback made an outbound LINE call for any unknown `kid`, reachable without authentication.                                                                                                                                    | The fallback is off in `cmd/api`: LIFF tokens are ES256 and verifiable locally; JWKS downloads are capped at one per minute whether or not the last one succeeded.                                                                                                                                                                                                                                                                                                                                     |
| P4       | JWKS set never expired and failed fetches did not back off.                                                                                                                                                                                         | Key sets older than 24 hours are refreshed before use; the one-minute floor applies after failures too.                                                                                                                                                                                                                                                                                                                                                                                                |
| P4       | Unverified channels were acceptable ID-token audiences.                                                                                                                                                                                             | Outside development only channels with `verified_at` count (`RequireVerifiedChannels`).                                                                                                                                                                                                                                                                                                                                                                                                                |
| P4       | Unused, unscoped queries.                                                                                                                                                                                                                           | `GetAppByOAChannelID`, `GetAppChannelsByChannelID`, `SetAppChannelVerified` removed.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| P4       | Invite token lingered in browser history and could leak through referrers.                                                                                                                                                                          | The page reads the token once and removes it from the address bar; the dashboard sends `Referrer-Policy: no-referrer`.                                                                                                                                                                                                                                                                                                                                                                                 |
| P4       | `oa_basic_id` from LINE was stored unvalidated.                                                                                                                                                                                                     | Autofill applies the same length and prefix rules as user input.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| P4       | `%`, `_` and `\` in member search changed the LIKE pattern.                                                                                                                                                                                         | Escaped; search is literal.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| P4       | `Export` was callable for API keys without an audit row.                                                                                                                                                                                            | Refused for non-users in the service.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| P4       | Accepting an invitation left no tenant audit row.                                                                                                                                                                                                   | `team.join` recorded in the acceptance transaction.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| P4       | Webhook events had no age check while dedupe rows expire after 7 days.                                                                                                                                                                              | Events older than 7 days are ignored.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| P4       | `GetApp` during API-key authentication ran in system mode.                                                                                                                                                                                          | Runs under the key's tenant scope.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| P4       | No test pinned cross-origin protection behaviour for LINE's webhook POSTs.                                                                                                                                                                          | `TestWebhookPostsWithoutFetchMetadataAreNotRefusedAsCrossOrigin`.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| P4       | The SDK fell back to `Math.random` for idempotency keys.                                                                                                                                                                                            | Throws `no_crypto` instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## Accepted for now, with a dated plan

| Severity | Finding                                                                                                                                               | Plan                                                                                                                                                                                                                                                                                       |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P2       | Opening an invite link does not prove ownership of the email: the inviter receives the link and can create the account for a new address.             | Email delivery of invitation tokens in Phase 6 (developer experience, when outbound email exists), after which `invite_url` is returned only in development. Until then invitations are owner/admin only, audited, and an existing account can never be entered through the link (P1 fix). |
| P4       | HS256 ID tokens are accepted when a channel secret is configured, which lets anyone holding the secret mint member sessions; LIFF never issues HS256. | Phase 3: make HS256 opt-in per app (web-login apps only).                                                                                                                                                                                                                                  |
| P4       | Channel token cache is keyed by channel ID only.                                                                                                      | Phase 5 (push messaging): key by channel ID plus a hash of the secret, and call `Forget` when a secret changes.                                                                                                                                                                            |
| P4       | Staff can read member PII (phone, birthday, LINE user ID); staff can list invitations.                                                                | Phase 3 role model: a redacted member shape for staff.                                                                                                                                                                                                                                     |
| P4       | No per-tenant member session revocation.                                                                                                              | Phase 3: `apps.member_sessions_valid_from`.                                                                                                                                                                                                                                                |

## Confirmed clean

ID tokens pinned per algorithm with no key confusion, `alg` none and RS256 rejected, `aud` checked before any key lookup; member sessions bound to tenant and app with `typ` separation from dashboard and MFA tokens; all Phase 2 tenant tables under forced RLS with the standard policy and no DELETE grant on members or consents; webhooks verified on the raw body with constant-time compare before any parsing, 1 MiB cap, dedupe and apply in one tenant transaction, no LINE call in the request path; credentials proven by minting a stateless token and stored envelope-encrypted; invitations 256-bit, hashed, clock-driven expiry, one pending per email; recovery codes HMAC under an HKDF-derived key; SDK keeps the session in memory and reuses the idempotency key on its single retry.
