# Phase 1 security review

Date: 2026-11-09. Scope: `main` after the platform, auth and dashboard merges. Reviewer: the read-only `security-reviewer` agent, every finding verified by reading the code path end to end. This page records the findings, what was fixed before the Phase 1 checkpoint, and what is deferred to a later phase with an owner.

## Fixed before the checkpoint

| Severity | Finding                                                                                                                                         | Fix                                                                                                                                                                                                                                                                                                           |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | Client IP came from the first `X-Forwarded-For` entry while nginx appends the peer, so per-IP rate limits and audit IPs were attacker-chosen.   | `clientIP` reads the last entry when `TRUST_PROXY=true`; the header is ignored otherwise. `TRUST_PROXY` is mandatory behind any proxy.                                                                                                                                                                        |
| P2       | MFA: no per-account attempt limit, the challenge token stayed valid for 5 minutes and after success, TOTP codes were replayable for up to 90 s. | `mfa_challenges` table: one row per challenge (`jti`), each attempt increments a counter, the challenge dies after 5 wrong codes and is marked used on success. `users.totp_last_step` records the last accepted 30-second step; a code for an older or equal step is refused. Per-user limiter on MFA codes. |
| P2       | No request body size limit in the API itself.                                                                                                   | 64 KiB `MaxBytesReader` middleware; oversized bodies answer 413 `payload_too_large`.                                                                                                                                                                                                                          |
| P2       | The refresh "lost response" allowance let a replayed stolen token mint a live second branch indefinitely.                                       | The allowance only applies within 60 s of the rotation. When a token is rotated and a sibling (another child of the same parent) was itself already rotated, two branches are live and the whole family is revoked. Two tabs stay safe because the unused branch is never rotated.                            |
| P3       | `sessions_valid_from` at nanosecond precision could reject the session issued in the same millisecond.                                          | `ChangePassword` and `LogoutAll` truncate to the millisecond.                                                                                                                                                                                                                                                 |
| P3       | Idempotent replays skipped authorization.                                                                                                       | `idempotency.Request.Before` runs the membership check inside the transaction before the key is claimed or replayed.                                                                                                                                                                                          |
| P3       | Expired idempotency outcomes still replayed; no cleanup job ran.                                                                                | Stale rows are deleted before the claim; the worker runs an hourly maintenance loop (expired idempotency keys, spent refresh tokens, old MFA challenges).                                                                                                                                                     |
| P3       | Cookie routes relied on `SameSite=Lax` alone.                                                                                                   | `http.NewCrossOriginProtection` wraps the API with `DASHBOARD_ORIGIN` trusted; cross-site requests answer 403 `cross_origin`.                                                                                                                                                                                 |
| P3       | No rate limit on the current-password check when changing the password or disabling TOTP.                                                       | Per-user limiter (5 per minute) on both.                                                                                                                                                                                                                                                                      |
| P4       | Client `X-Request-ID` flowed into logs unfiltered.                                                                                              | Only `[A-Za-z0-9_-]{1,64}` is accepted; anything else is replaced.                                                                                                                                                                                                                                            |
| P4       | argon2 parameters were read from the stored hash without bounds.                                                                                | Memory, iterations and parallelism are clamped; out-of-range hashes are refused.                                                                                                                                                                                                                              |

| P2 (test-engineer) | Under parallel replay of one rotated refresh token the allowance was unbounded: the children check ran outside the insert transaction. | The rotated row is locked (`SELECT ... FOR UPDATE`) and children are counted inside the transaction that inserts the replacement; a race-loser also re-reads the token before the window check so a concurrent rotation is not mistaken for a late replay. Covered by `TestConcurrentRefreshAllowanceIsBounded` (8 goroutines). |

## Test-engineer pass

A separate agent built a spec-driven coverage matrix (`internal/httpserver/coverage_*_test.go`): every one of the 40 operations is checked for cross-tenant 404 with no state change, role rules, idempotent replay and mismatch, and wrong-credential-kind rejection; every tenant table is proven isolated and its grants checked; 21 forged-token shapes, cookie attributes, log hygiene (no credential ever appears in debug logs) and concurrency races are covered. Test functions went from 89 to 117 and the suite runs clean under `-race`.

## Rate limit defaults

Per client IP 30 per minute on register, login, MFA and refresh (offices share one address); per email 5 per minute on login; per user 10 per minute on MFA codes and current-password checks; 5 wrong codes kill an MFA challenge.

## Conventions confirmed by the review

- All nine tenant-scoped tables have forced RLS with the standard policy; the application role owns nothing and cannot bypass RLS; every `WithSystem` use is a single-column lookup.
- Handlers derive scope from the principal or a path ID plus membership check, never from the body.
- Secrets never reach logs or responses: only `*_secret_set` booleans are returned; all `slog` call sites were checked.
- DELETE operations take no `Idempotency-Key`: repeating one is a 404, which is the documented exception to "every write".
