Notes on the re-review fixes:

- R3: role membership is cluster-wide. Applying 00011 to one database takes the membership away in every database on the cluster, so each database needs 00011 before its worker runs again. The integration tests share one cluster, so `testutil` holds a cross-process advisory lock: migrations that change the membership take it shared, and tests that assert what the worker may not do take it exclusively.
- R5: a void made before an erasure keeps its stored idempotent outcome, which holds the reason, until the 24-hour TTL ends and maintenance deletes it. Nothing can replay it, because authorization now refuses the erased member first.
- R2: the API key limiter runs before the idempotency replay, like the other limiters, so a retry spends a token.

## Deliberate choices

- F1: the visit window is 30 minutes and counts every stamp of the member on the card, from any scan and any staff member. A second visit within 30 minutes cannot get more stamps. That is the product decision. Dashboard adjustments are not stamps and do not count.
- F1: a stamp leaves the window 30 minutes after it was given, so one visit's stamps free up one by one, not all at once.
- F2: three redeems per scan covers a customer using a few coupons in one purchase. A scan used for a points redemption and a scan used for coupons are counted apart: points still allow one redemption per scan.
- F3: the claim and API limiters, like the staff limiter, run before the idempotency replay, so a retry spends a token. Limits are per API process, which is exact for the single VM deployment. Dashboard issues are not limited; they need an owner or admin and are audited.
- F8: the void reason stays on the coupon until an erasure, because staff need it while the member exists. Completion rows keep the `reward_unavailable` marker, which is not personal data and drives the unrewarded count.
- F9: when the API starts enqueueing jobs, a new migration grants `miniloyal_api` `SELECT` and `INSERT` on `river_job`, `UPDATE (kind)` and the sequence again. The guard trigger on `river_job` stays in place for that day.
- F9: `make dev` reads `.env`. `.env.example` sets both passwords, and compose stops with a clear message when one is missing.

## Confirmed clean

Every coupon issue locks the template row, so `total_limit` and `per_member_limit` hold under races. A redeem is one conditional update. Stamps lock the progress row before writing events. Composite foreign keys keep every reference inside one app. New tables have forced RLS with the standard tenant policy or `system_only`. Outbox payloads carry IDs, counts and amounts only.
